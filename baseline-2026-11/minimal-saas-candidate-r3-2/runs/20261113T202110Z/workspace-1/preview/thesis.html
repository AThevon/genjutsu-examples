Ploverdesk - thesis preview

This page is the proposal, not the build. It is throwaway; the landing page is built from the theses, not from this markup. Status: UNVALIDATED (headless run, nobody to approve).

Visual thesis

Visual thesis: A cool white page set in graphite ink, flat and hairline-ruled like an auditor's working paper. One deep near-black marks the action (the trial button). One audit red is used for nothing except a line that does not match. The type is the system sans with tabular figures, because the product's voice is its numbers lining up. The first screen is a three-way match of one example invoice, at rest: matched lines receded to grey, the exceptions in full ink with the differing value in red.

Allowed patterns: hairline rules (they are the table rules of a working paper); tabular figures; one table as the hero object, labelled as an example; the system font stack (a choice, see type).

The red is not an accent. It never appears on a button, a link or a heading: it is the pencil mark on a discrepancy. The action stays in ink.

Type (system sans, tabular figures)

Only the lines that do not match reach your desk.

Lead 18/1.5 - Ploverdesk reads supplier invoices that arrive by email as PDF.

Body 16/1.5 - weight 400; 500 for labels and buttons; 600 for headings only.

Small 13 - column headers, the example label.

Why no web face: no font request leaves the page. A product that sells "data hosted in Frankfurt" should not send each visitor's IP to a third-party font CDN, and finance teams will see the page in the same system face their accounting tools use. The voice comes from tabular figures, weight contrast (400 / 600) and the table, not from a face.

Spacing

4px base. One left edge (1120px container, 48px side padding wide, 16px narrow). Running text at 62ch; the match table takes the full container, its width set by its five columns.

Interaction thesis

Interaction thesis: Fast and dry (120-240ms, cubic-bezier(0.2, 0, 0, 1)): hovers change only a background or an underline in 120ms, scroll does nothing, and the one motion is the match itself. On load the matched lines settle from full ink to grey (240ms each, 60ms stagger, after 400ms), so the exceptions are what stay. Forbidden: scroll reveals, parallax, scale on hover, bounce, looping animation, counters, shadows, gradients, glass.

The one motion: trigger: first paint. Before it runs: every line in full ink. If it never runs, or with reduced motion: the resting state is the end state (matched grey, exceptions red), so the idea is shown with no motion at all.

Settle 240ms - stagger 60ms - delay 400ms - hover 120ms.
